# 안전하게 올리기 (safe-push)

비전공자가 만든 코드를 깃(GitHub)에 올리기 전에 **비밀 값이 섞여 들어가지 않았는지** 확인하고 푸시합니다.
한 번에 다 자동으로 하지 말고, 아래 순서대로 확인하며 진행하세요. 문제가 있으면 **멈추고** 한국어로 쉽게 설명합니다.

## 순서

1. **안전장치 켜져 있나 확인**
   - `git config core.hooksPath` 가 `.githooks` 인지 확인. 아니면 켜고(`git config core.hooksPath .githooks`) `.githooks/pre-commit`에 실행권한을 줍니다.

2. **무엇이 올라가는지 확인**
   - `git status` 와 `git diff --cached --stat` 로 어떤 파일이 바뀌었는지 사용자에게 쉽게 요약해줍니다.

3. **비밀 파일이 포함됐는지 검사**
   - 스테이징/추적 목록에 `.env`, `.env.local` 등 비밀 파일이 있는지 확인 (`git ls-files | grep -E '(^|/)\.env'`).
   - 있으면: 멈추고, `git rm --cached <파일>` 로 추적에서 빼고 `.gitignore`에 들어있는지 확인하도록 안내.

4. **코드 속 비밀값 검사**
   - 변경된 코드에 API 키·토큰 패턴(`sk-...`, `AKIA...`, `mb_...`, `gh*_...`, 긴 토큰, private key 등)이 있는지 검사.
   - 발견되면: 멈추고, 그 값을 `.env`로 옮기고 `process.env`로 부르도록 고친 뒤 다시 진행.

5. **커밋 & 푸시**
   - 문제가 없으면 의미 있는 한국어 커밋 메시지로 커밋합니다. (pre-commit 검사가 한 번 더 자동으로 돕습니다)
   - 원격(remote)이 있으면 `git push` 합니다. 없으면 어떻게 연결하는지 안내합니다.

## 규칙

- 검사를 **`--no-verify` 등으로 우회하지 않습니다.** 막히면 원인을 고치는 게 맞습니다.
- 비밀 값이 이미 올라간 정황이 보이면: 숨기지 말고 **키를 재발급**해야 한다고 알리고(리더에게 문의), 그 다음 코드를 고칩니다.
- 사용자가 직접 `git push` 하려 하면, 먼저 이 검사를 거치도록 권합니다.
